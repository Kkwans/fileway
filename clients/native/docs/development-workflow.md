# 原生客户端连续开发工作流

目标是Android优先、Windows后续；保留原生架构，不因安装了React/shadcn技能而迁移技术栈。当前任务阶段与外部动作以当前用户授权为准。

## 新会话启动

最新阶段门禁：先在Plan模式只读核验并编写计划，用户确认/点击执行后才进入Goal实现和交付。必读 [媒体体验需求](media-experience-plan-input.md) 与 [复用研究](media-reuse-research.md)。旧交接直接执行授权不再适用于新会话的初始Plan阶段。真机ADB最早2026-10-07晚可配合，不影响独立规划；正式验收不能提前视为通过。

1. 先读当前 `AGENTS.md`、[最新交接](handoff-2026-10-06.md)、[设备与媒体新增要求](device-media-acceptance.md)及私有交接包的2026-10-06补充。记录实际分支、HEAD、remote和dirty归属，核对公开APK与main差异。旧DELIVERY.json是历史快照，不代表后续文档和工作树没有变化。
2. 先核验已实现功能，不重做缓存、图片查看、手势和五布局。保留三处旧实验，不随常规功能提交。用户取消的130%/200%字号检查不恢复；普通字体、TalkBack、横竖屏、明暗和大屏要求仍保留。
3. 拆出有明确完成标准的小切片：设备安全接入/播放可观测性、原生可靠性、解码/质量入口、连接与会话、文件/搜索、设置、播放器视觉交互。根据真实依赖调整；缺真机只阻塞相关门禁，不停止独立工作。

## 分布式执行契约

NAS负责源码和调度；既有Windows机器通过SSH/PowerShell运行Gradle与ADB，Linux x64 CI负责可复现构建/原生库与模拟器门禁。具体主机地址与私有脚本位置仅在私有交接包，不写进公共仓库。

先复用现有脚本，再逐步整理参数化入口；本文件不表示入口已实现。每次job记录源码SHA（实验附patch/hash）、工具链、native库hash、APK/test APK hash、签名/版本、设备API/ABI、测试数和结果。源码暂存目录不能自动等同于发布源码。

共享Windows staging/cache、模拟器和真机使用所有权锁，防止双会话交叉覆盖。连接断开先核对远端job结果再重试；超时不等于任务失败或安全重放。证据传输验证hash，测试失败也导出报告，保留原始非零状态。禁止全局kill adb/emulator、删缓存、清设备来掩盖问题。

## 每切片及最终门禁

- 切片：受影响测试、lint/构建、差异审查、`git diff --check`；当前已授权commit/push时精确暂存、独立提交并立即FF push。未授权时保留本地修改并报告，不从旧提示词继承外部写入权限。
- UI页面域：实际截图、长/空/错误/加载状态、键盘/触摸/旋转/系统栏交互；动效加实时/录屏/trace，不能只看静态图。功能正确和视觉质量分开验收。早期代表性页面先确立可接受方向，再扩展全域。
- 最终：明确已推送SHA的干净源码 → 全量测试/构建 → 签名/ABI/对齐/版本校验 → 模拟器与真机 → 覆盖升级 → 发布。预览允许明示未完成门禁，不冒充正式版。发布动作需当前授权。
- 回滚保留前包、证书、源码与兼容数据备份；不能默认旧APK能覆盖降级新数据库。

## Windows阶段

复用协议、网络核心、样本及验收模型；UI/生命周期与平台媒体绑定分别实现。先验证最小WinUI窗口、原生播放、Go接口、HDR及打包链路，不照搬Android JNI或Surface实现。SSH编译成功不等于交互桌面可用：窗口/UI Automation、DPI、多显示器、键鼠、文件对话框、全屏和HDR验收需单独授权且可用的Windows桌面会话。不要因Android远程构建已通就宣称Windows客户端测试平台完成。
