# Embedded route policy

Selected Tailscale traffic must use the embedded userspace network. The locked SDK's generic `Server.Dial` delegates to `UserDial`, which may choose a system socket for destinations outside tailnet routes. It is therefore insufficient as the only enforcement boundary.

The client now classifies the destination with `UserDialPlan`, requires ownership by the embedded netstack, and invokes `NetstackDialTCP` with the returned IP/port. It never passes the hostname to a second general dial. Route withdrawal after classification may fail the request, but cannot redirect it to the system LAN. HTTP Host and TLS certificate validation retain the original service hostname.

This adapter uses `Server.Sys`, an explicitly unstable SDK API. Its use is isolated in `core/tailnet/node.go` and locked to tsnet 1.102.5. Dependency upgrades require source review of route classification and netstack-only dialing, compiler/native checks and the routing regressions; no reflection or unsafe access is used.

Tests cover a reachable LAN destination denied by route policy, a resolved overlay IP with original TLS/HTTP host, and cancellation before resolution. These are controlled fixtures. Real node approval, approved 100/subnet routes, external mobile/Wi-Fi, direct/DERP and lifecycle proof still require devices and enrollment resources.

Pinned primary sources: [tsnet](https://github.com/tailscale/tailscale/blob/v1.102.5/tsnet/tsnet.go), [tsdial](https://github.com/tailscale/tailscale/blob/v1.102.5/net/tsdial/tsdial.go).

## Android first-login correction (2026-10-04)

The actual API35 JNI first-start gate failed before authentication with `tsnet: route ip+net: netlinkrib: permission denied`. Target API30+ apps cannot use Go's netlink interface enumeration. The pinned SDK explicitly offers `netmon.RegisterInterfaceGetter` for this boundary. Android now supplies Java interface addresses and ConnectivityManager default-link updates through a control-only snapshot; the Android Go build registers the snapshot provider once. Empty snapshots represent loss of connectivity, never permission to fall back to direct media dialing. Readers receive deep copies under a lock, and network changes wake the embedded monitor.

The next actual startup exposed `logpolicy.LogsDir` panicking because this Android process has no writable default HOME/cwd/temp directory. The Android adapter prepares a private no-backup logs directory and sets the SDK's `TS_LOGS_DIR`; it does not modify HOME or shared storage. Failed SDK initialization is recovered at the node boundary, closes initialized resources, and replaces the instance whose initOnce would otherwise cache the failure. The encrypted identity store is retained. Early failures before Sys exists skip upstream Close, whose implementation dereferences Sys.

Logout is now an affirmative capability from the persisted SDK user identity, not inferred from a negative list of UI states. Stopped nodes hide login URLs; restarting starts the interactive flow again. Stopping the embedded node disconnects an active embedded NAS session but preserves a direct NAS session.

Validation: Go 1.26.6 `go test ./...` and `go vet ./...` passed, including invalid snapshot preservation, host-IP preservation, immutable/concurrent snapshots and two failed initialization retries retaining the same encrypted store. TX5Pro built both native ABIs and passed `:app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug :app:testDebugUnitTest` (the local unit task is NO-SOURCE). Installed API35 `EmbeddedLoginTest` with `-e embeddedLoginAcceptance true` passed **3 tests in 18.768s**, contacting the actual official control service without an auth key or node approval: valid HTTPS login URL, no connected/logout claim, stop/restart, and actual connection-page connect/login-entry/cancel. A synthetic-input UI screenshot was captured. Offline CI skips the two external login tests by default and still tests the logout capability.

NAS-local `go test -race ./...` cannot execute because this host has no gcc; Linux [Go workflow 37176047146](https://github.com/Kkwans/nas-file-browser-client/actions/runs/37176047146) passed race and vet on `6d66851`. The API35 full-device report had 57 tests and four failures: two known ASS failures, plus two external-test runtime assumptions that UTP incorrectly counts as failures. External acceptance now uses a runtime annotation and AndroidJUnitRunner's discovery-time `notAnnotation` filter through Gradle. Explicit adb class selection runs the real login tests; no runtime assumption or weakened assertion is used. Authenticated enrollment, phone lifecycle, external 100/subnet media and Clash coexistence remain pending. No VpnService or system tunnel is introduced by this adapter; that code fact does not prove coexistence on a phone. This slice is not an APK release; rollback is the preceding main commit `609efc1` and the existing 0.2.1 package/state backup.
