# 图片与视频体验重做：Plan输入与验收清单

2026-10-06用户新增要求。本文件是明确需求和候选方案，不是已批准的技术实现计划，也不表示功能已完成。新会话必须先Plan只读核验并产出计划，待用户确认/点击执行后才进入Goal开发交付。此前“直接继续实现”启动语句由此覆盖。

## 资源与当前证据

- 小米14（用户报告澎湃OS3、Android16）ADB最早 **2026-10-07晚，Asia/Shanghai** 接入TX5pro；具体时段未约定。不要提前反复要求接线、自动建定时任务或声称已真机测试。此前可做计划、代码核验及已授权的独立工作；远程构建/模拟器是否可用仍需现场确认，不把“人不在电脑旁”等同于电脑一定离线。
- Tailscale外网成功为USER_VERIFIED，保留既有结论；HDR/实际解码/长片等另行验收。
- 本轮源码核验：ImageScreen有基础缩放/平移和Coil加载，但无左右图片分页及预览到原图的两阶段展示；不能称完全没有图片功能，也不能称完整图片浏览器。
- MediaThumbnail在非成功状态统一使用 `art_play`，图片兜底语义错误；加载、无预览和失败区分不足。
- PlayerSlider使用10dp自定义thumb与3dp Canvas轨道。用户报告圆点未居中，作为待修缺陷；源码说明需要检查轨道可用宽度、thumb中心与padding的统一映射，未在本轮重跑UI，不能仅靠源码宣布根因。
- PlayerScreen已有双击播放/暂停、长按倍速等部分逻辑，新增分区手势必须重构其仲裁而非再叠一套探测器。原有快进/快退按钮是步进seek，不是上一首/下一首。
- licenses中记录部分图标从ArtPlayer SVG转为VectorDrawable；现状不是全部手绘，但跨图标集的视觉一致性与最终渲染不合格反馈必须处理，不以有许可证或来源为验收。

## I：完整图片浏览器

| ID | 必须覆盖 | 验收要点 |
| --- | --- | --- |
| I1 | 左右滑动上一张/下一张 | 以当前目录或搜索结果的已确定顺序建立图片队列；稳定身份，不依靠文件名；首尾、分页、目录变化行为明确 |
| I2 | 先预览，再原图 | 优先显示已有缩略图/预览；原图加载期间保留预览并叠加克制转圈，不闪白/黑屏，不让旧请求替换新页 |
| I3 | 加载与失败 | 原图失败时保留可用预览、显示重试/取消；明确“预览图/原图”，无权限/不存在/网络失败/无预览分别处理 |
| I4 | 成熟缩放交互 | 复用支持双指、双击缩放、平移约束与大图分块的原生组件；放大平移与横向翻页不抢手势 |
| I5 | 连续浏览质量 | 相邻预取有并发/内存/磁盘预算；仅缓存命中不得伪显示网络速度；大图、长图、EXIF方向、透明图、损坏图和快速翻页测试 |

队列范围（当前目录/当前结果/是否递归）、分页加载和首尾是否循环由Plan给出推荐并确认，不能默认下载整目录原图。切换账号/服务器取消旧请求、清除旧队列可见状态；保留实际账号隔离和已有缓存策略。返回文件列表保留位置。动画格式和更多图片格式列入支持矩阵，不承诺未测格式。

| ID | 必须覆盖 | 验收要点 |
| --- | --- | --- |

用户明确功能为必需；播放结束自动下一项、循环/随机、水平滑动seek、PiP/后台播放等作为Plan建议/后续项单列，不无声扩大首期。锁定模式、TalkBack和控件区域必须可禁用/替代手势；不要让调音量吞掉进度条、列表或系统返回。不可seek、未知时长、直播等状态明确禁用对应动作。

## S：字幕调节

- 文本字幕在引擎能力允许时支持字号、垂直位置/底边距调节、预览和重置；缩放后避开安全区与控制条，旋转保持合理位置。
- 普通SRT/VTT文本、带作者样式/定位/动画的ASS、位图PGS分别评估。位图字幕不能承诺改变“字体大小”；ASS默认保留作者排版，是否覆盖样式需单独可理解的选项。能力不支持时说明原因，不显示可点击却无效的滑块。
- 评估字幕延迟、描边/背景等常见能力，列为建议而非偷偷扩大当前必需范围。已有关闭字幕/切轨/外挂字幕/seek回归不得丢失。
- 先查固定libVLC API与渲染链；不要叠第二个字幕渲染器导致重复、不同步或破坏ASS/PGS保真。用户设置保存作用域及是否按片记忆在Plan明确。

## C：字幕/音轨/倍速切换的播放连续性（新增必修缺陷）

用户实机反馈：切换字幕、音轨、倍速时视频卡顿、可能丢失声音，体验不合格。记为USER_REPORTED_FAILURE，三类分别复现与取证；本轮尚未重跑设备，不能猜测已确定根因。该问题属于当前媒体体验重做的必需范围，不得只换UI后延期为“后续优化”。

- C1 字幕：关闭/开启、文本/ASS/PGS/外挂字幕之间切换，检查声音不中断、视频时钟持续、字幕正确出现/清除、无旧字幕残留或双层字幕；包括菜单关闭后实际画面，不能只检查selected ID。
- C2 音轨：同编码和跨编码、声道/采样率变化、未知/不支持轨道分别测试；允许引擎必要的可解释短重配，但不能长时间卡死、持续静音、回到开头或静默变为其他音轨。记录切换请求到可听声音恢复时间、画面连续性与音画同步；“有音轨/音量大于0/播放器Playing事件”不证明声音输出。
- C3 倍速：暂停/播放/缓冲/seek期间及连续快速选择速度、长按临时倍速和松手恢复，验证实际速率、音频time-stretch、音画同步及恢复；不得仅改变界面数字。暂停时选择倍速不擅自开始播放。
- C4 组合压力：切换音轨后切字幕/倍速，旋转、后台恢复、重连与切换视频/服务器同时到来，最后一次有效请求胜出；拒绝旧媒体回调覆盖新会话。失败有明确反馈，可恢复到原设置或提供重试，不假显示成功。
- C5 状态保护：保留当前播放位置、用户暂停意图、倍速与选轨策略；检查不必要的重新open/setMedia、重复Surface绑定、播放器实例重建、音频焦点、线程/事件顺序、缓存/lease取消及Compose effect键变化。它们是排查路径，不是已确认根因；以真实日志和稳定复现判断。
- C6 证据：每次记录媒体/轨道格式、构建SHA、引擎版本、设备/API、操作顺序、首个异常事件、切换耗时、时间戳连续性、音频与视频实际输出。优先固定短样本与可复现音频fixture；手机扬声器听感、系统音频路由和客观输出可用证据分开，禁止录制无关麦克风/通话。外放/蓝牙分别验收，设备未提供的路径单列。

Plan必须给出切换状态机、操作串行/合并与错误恢复、实际观测手段、稳定复现和回归矩阵。延迟/同步阈值先复核原已批准媒体指标，不私自放宽；正常设置操作不应出现可感知的非必要卡顿。若引擎的必要重配置或设备能力有不可消除边界，应给出测量和备选方案让用户判断，不承诺所有编码轨道绝对零延迟。

“一次性做好”落实为跨功能状态机和完整回归，不解释成一次大提交：图片/播放器底座与媒体连续性先设计清楚，按独立切片提交，最终用组合矩阵统一验收。未通过不得把该切片或整体Goal标为完成；禁止降低断言、静音或隐藏控件来制造通过。

## B：缓冲、实时速度与缓存

- 显示当前播放会话实际网络读取速率，自动格式化KB/s、MB/s并明确十进制/二进制口径；用单调时钟与短窗口平滑，空闲衰减到0或显示空闲，不保留陈旧峰值。
- 在Go transport/lease边界评估采样：区分上游网络读取、磁盘缓存命中、向本地播放器发送的字节；不把localhost复制速度或其他图片请求合并成视频下载速度。不泄露URL、token或真实路径。
- 区分三件事：播放器一次缓冲事件的百分比、已缓存文件字节范围、可连续播放的时间范围。libVLC Buffering事件100%不等于整片已缓存。
- 时间轴需要已播放/可播放缓冲/未加载层及seek thumb。仅在引擎或索引能可靠给出时间范围时绘制缓冲段；原始VBR/MKV稀疏Range缓存不能用“已下字节÷总大小×时长”伪造时间覆盖。能力不足时显示真实字节缓存统计与不确定状态，Plan必须明确可实现程度。
- seek清理过期指标，多个Range并发有统一会话口径，取消/切片/切服务器拒绝迟到采样。下载速度不等于码率、吞吐上限或首帧速度。
- 检查既有磁盘缓存配额、清理、分片完整性/命中、账号隔离和206/416；避免为进度条引入第二套缓存或无上限预下载。进度拖动缩略图依赖既有预览能力，能力不足不可假图代替。

## U：统一视觉、图标与加载状态

- 选一个主图标家族和同一风格，不混搭ArtPlayer/随意SVG/Unicode；上一项、后退10秒、播放列表应有不同且标准的语义。原始素材引用、版本、许可与转换记录完整。
- thumb与track共用实际可用坐标，检查0/25/50/75/100%及拖动、禁用、横竖屏/密度；光学中心和触控命中区域都要正确。测试输出实际截图，不只测数值。
- 文件列表：首次加载用稳定布局占位/骨架；刷新保留旧内容和轻量反馈；分页在尾部反馈。避免每格独立高速转圈或大面积闪烁。
- 图片：原比例预览底图＋原图加载转圈；无预览使用图片语义占位。视频可用视频类型占位；文件夹、普通文件不能统一播放三角。失败状态有重试且不无限转圈。
- 播放器：初次连接、开流、解码等待、缓冲、暂停与失败分开；速度与状态贴合实际，不用假百分比/装饰性倒计时。加载HUD不改变视频Surface尺寸、不遮挡主要字幕。
- 所有加载/状态切换统一大小、颜色、节奏、延迟显示策略及减少动画处理；先保证有反馈，再消除快速完成时的闪烁。无需为普通spinner引入大型动画库。

## Plan必须交付的内容

1. 功能/缺陷矩阵：上述ID（包括C1–C6切换连续性）、当前源码证据、是否已有、差距、依赖、验收、优先级；主动补查同类边界，不等用户逐个发现。
2. 复用决策：读 [组件与素材候选](media-reuse-research.md)，比较直接依赖、适配既有组件、合规复用局部实现与自研的成本；不是只列链接。
3. 视觉方案：播放器和图片浏览器各一个代表性布局，统一图标/色彩/尺寸/轨道/加载态；示意与实际截图明确区分。默认Material控件不是审美通过理由。
4. 技术设计：队列来源/状态机/手势仲裁/取消/缓存与速度遥测/字幕能力分层、测试隔离、许可证和升级风险。
5. 切片与门禁：先原生切换连续性/可观测性与基础视觉/可复用底座，再图片、视频队列/手势、字幕、缓冲，按依赖调整；每切片单独测试/CR/commit/FF push，最终完整组合复验与已授权预览交付。不卡死、不持续丢声、不破坏音画同步是播放门禁，不得留待UI交付之后补救。
6. 少量真正未决语义：队列与循环、音量作用域、双击步长、硬解回退策略、转码授权等，已有要求不得重问。提出推荐并形成最终契约。
7. 10月7日晚真机接入前后分别能完成什么；缺设备不伪造通过，不阻塞独立任务。完整HDR/音频/整片证据另列。

Plan期间不改App、不装依赖、不创建执行Goal、不发布。用户确认计划/点击执行后按已批准范围创建或使用Goal连续完成实现、精确提交推送和交付；若实际客户端Plan切换只能由用户操作，明确提示切换并保持只读规划，不能声称文字提示已切换产品模式。未完成不得标记Goal完成；不启动重复目标。Windows保留后续独立阶段。
