# NAS 文件浏览器 UI、移动端与 Markdown 重构规格

> 状态：待实施
>
> 基线：`master` / `09fb6e9`
>
> 日期：2026-07-13
>
> 范围：前端视图、响应式布局、交互状态与 Markdown 编辑/预览；不包含部署和运行中服务变更

## 1. 结论

当前问题不是若干独立 CSS 瑕疵，而是布局架构失效：同一套 DOM 同时承担桌面表格、移动端列表、详细网格和紧凑视图；`listing.css`、`mobile.css` 又通过多轮追加覆盖争夺同一批选择器，运行时还有 JavaScript 直接改写网格宽度。继续追加“最终覆盖”只能短暂遮住一个截图中的问题，并持续制造新的错位、裁切和断点冲突。

本轮必须采用“删除旧契约、建立单一布局来源”的方式重构：

1. 桌面详细列表使用真正共享列定义的语义表格，不再用多个互不关联的 Grid 模拟表格。
2. 移动端详细列表使用专用卡片 DOM，不渲染桌面表头，不横向滚动，也不逐行展示五个大型操作按钮。
3. 网格视图只由 CSS Grid 决定列数，删除运行时修改 CSS 规则的 `columnsResize()`。
4. 顶部工具栏拆成左、中、右三个明确区域；移动端菜单在左，搜索和更多在右。
5. Markdown 编辑、预览和代码块共享一套浅色主题；深色样式只在应用明确启用深色主题时生效。
6. 代码块语言、语法高亮和行号必须由内容及用户设置驱动，不能靠固定深色背景或永久伪元素模拟。

## 2. 证据与根因

### 2.1 用户截图揭示的问题

| 证据 | 可见问题 | 根因判断 |
| --- | --- | --- |
| 移动端详细列表 | 名称、类型、大小整列丢失，只剩修改时间和操作；操作图标溢出；底部出现空白选择面板 | 桌面宽表格被压缩/裁切；移动端仍使用桌面列布局；选择工具栏无条件渲染 |
| 移动端详细网格 | 面包屑多行挤压；筛选栏过高；文件名只显示两三个字；卡片空白过多；搜索和更多按钮集中到左侧 | 工具栏没有区域契约；卡片固定高度与文本宽度不匹配；响应式规则相互覆盖 |
| 桌面详细列表 | 表头与内容不对齐；名称列内部断裂；分隔线位置错误；操作区视觉噪声大 | 表头与数据行采用不同 Grid/内边距；图标位于列网格之外；多轮覆盖产生魔法数补偿 |
| Markdown 编辑 | 浅色应用中出现整块深蓝编辑区，文字对比不足，与其他页面割裂 | Vditor 主题、应用主题和高亮主题各自判断，没有统一状态源；高优先级覆盖强制深色 |
| Markdown 预览 | 代码块固定深色且阴影过重；左侧出现透明空框；没有行号开关 | 代码块永久添加行号类和固定宽度伪元素；浅色模式仍强制深色代码块 |

### 2.2 源码中的结构性问题

- `frontend/src/css/listing.css` 已接近 2000 行，同一视图选择器被多次重定义，并存在多个“最终契约”式尾部覆盖。
- `frontend/src/css/mobile.css` 先于 `listing.css` 加载，双方都修改移动端网格宽度、标签按钮和列表布局，最终结果依赖导入顺序而非组件契约。
- `FileListing.vue` 的 `columnsResize()` 在窗口变化时直接查找并改写 `.mosaic .item` CSS 规则宽度，与 CSS Grid 同时控制列宽。
- `ListingItem.vue` 用一套层级结构承载四种视图。桌面表格的图标、名称、元信息和操作并不处于同一列模型，表头只能用 `padding-left` 等魔法数补偿。
- 移动端详细列表通过 `min-width: 52rem` 和横向滚动保留桌面列，导致手机只能看到中后部列。
- `FileListing.vue` 在移动端始终渲染 `#file-selection`，即使没有进入多选状态，也会形成遮挡内容的大型空面板。
- `HeaderBar.vue` 的菜单、默认插槽、动作列表和更多按钮按 DOM 顺序平铺，移动端没有 leading/title/trailing 分组，所以按钮集中在左侧。
- `mdPreview.css` 同时承担预览排版、代码块、Vditor 编辑器和深色主题覆盖，浅色规则中也强制代码块使用深色背景。
- `highlightAndAnnotateCodeBlocks()` 只处理已声明的 `language-*`，并无条件包装行、添加行号类；没有语言时不识别，没有关闭行号的状态入口。
- `isDarkTheme()` 使用完整类名字符串相等判断；高亮 CSS 又只加载一次，主题切换后可能继续沿用旧主题。

## 3. 设计方向与基础规范

### 3.1 产品气质

以 Windows 11 资源管理器为交互参照，但不逐像素复制。目标是克制、清晰、高信息密度、适合 NAS 长时间管理文件的工具界面。禁止渐变、玻璃拟态、夸张阴影、超大圆角和装饰性图标背景。

### 3.2 视觉令牌

实现时优先复用项目已有 CSS 变量，并将以下语义补全为统一令牌，禁止在视图组件中散落临时颜色：

| 语义 | 浅色建议值 | 用途 |
| --- | --- | --- |
| 页面背景 | `#F7F8FA` | 主内容背景 |
| 一级表面 | `#FFFFFF` | 卡片、表格、弹窗 |
| 二级表面 | `#F3F5F8` | 表头、悬停、输入区 |
| 主文字 | `#1F2937` | 文件名、标题 |
| 次文字 | `#64748B` | 时间、类型、说明 |
| 边框 | `#E5E7EB` | 表格分隔、卡片边界 |
| 主色 | 沿用项目蓝色 | 选中、焦点、活动态 |
| 危险色 | `#DC2626` | 删除悬停和风险提示 |

间距只使用 `4 / 8 / 12 / 16 / 24 / 32px`；卡片圆角 `10px`，弹窗 `12px`；普通阴影只用于浮层，列表和代码块不使用厚重投影。桌面操作热区至少 `40×40px`，移动端至少 `44×44px`。

### 3.3 响应式判定

不要只依据浏览器宽度猜测可用空间。侧边栏可调宽，因此详细表格应以列表容器宽度为准：

- 容器宽度 `>= 900px`：桌面详细表格。
- 容器宽度 `< 900px`：详细移动卡片。
- 视口 `< 737px`：手机工具栏、单行压缩面包屑、底部安全区。
- `737–1023px`：平板工具栏；视图本身仍由容器宽度决定。

优先使用 CSS Container Queries；不支持时以 `ResizeObserver` 只维护一个布尔布局状态。禁止 JavaScript 修改具体像素宽度或 CSSStyleSheet 规则。

## 4. 全局框架重构

### 4.1 顶部工具栏

将 `HeaderBar.vue` 重构为三个明确插槽/区域：

```text
HeaderBar
├─ leading：Logo 或移动端菜单
├─ center：桌面搜索框或移动端当前目录标题
└─ trailing：视图、排序、上传等动作和更多菜单
```

桌面端：Logo 固定在左；搜索框占据中间可伸缩区域，最大宽度不限制为小图标；动作靠右并垂直居中。移动端：菜单按钮在左；当前目录标题单行省略；搜索和更多在右。所有下拉菜单使用不透明一级表面、边框和轻阴影，并锚定触发按钮的右下方。

验收：360px 宽度下，菜单不会与搜索、更多聚在一起；标题不把右侧动作推出屏幕；PC 搜索框与其他动作垂直居中。

### 4.2 面包屑

桌面保持完整路径。手机只显示“主页 / … / 父级 / 当前目录”，单行且不换行；当前目录最多占可用宽度的 45%，超出省略。禁止每个路径段独立换行形成两三行导航。

### 4.3 标签筛选提示

桌面为单行紧凑条：标签图标、说明、作用域分段按钮、关闭。手机为两行：第一行说明和关闭，第二行全宽分段按钮。默认作用域为“全局”，打开筛选后提示条必须始终可见，且全局结果直接展示被标记对象，不得只返回其父目录。

### 4.4 移动端多选工具栏

只在 `multiple === true` 或 `selectedCount > 0` 时渲染。显示“已选择 N 项”和当前可用动作；未进入多选时 DOM 不存在。底部使用 `env(safe-area-inset-bottom)`，高度控制在 64–72px，不能形成只有一个图标的大型空白面板。

### 4.5 侧边栏

统一标题行、折叠按钮、计数和管理动作的基线；每个项目采用 40–44px 行高，图标、主标题、副路径、关闭按钮按固定区域对齐。操作按钮默认无背景，仅悬停出现浅色圆角表面。滚动条使用 6px 以内细轨道，不得覆盖拖拽调整侧边栏宽度的命中区。

### 4.6 搜索与标签筛选作用域

顶部搜索框默认“当前目录”，输入过程中不跳转，按 Enter 或点击搜索后进入结果页；侧边栏“搜索”继续进入专用搜索页。两处都必须允许切换“当前目录 / 全局”，但保留各自入口意图。当前目录搜索应以规范化后的当前路径作为根，不得因为前导 `/files`、URL 编码或尾部斜杠而查不到当前可见文件；全局搜索从用户有权限访问的根范围执行。

标签筛选与搜索共用相同的作用域模型。全局筛选直接返回被标记文件或文件夹，结果项携带原始完整路径供跳转，不能把命中的文件夹替换为父目录。当前目录与全局切换不得清空已选标签；刷新后仍应从用户持久化标签关系回显。

### 4.7 中文文案与标记组件

所有面向用户的文案必须原生中文，固定文件名、扩展名、协议和必要技术术语除外。禁止出现 `a month ago`、`search.images`、多余英文代码键或给普通中文选项添加装饰性单引号。时间格式化由统一工具输出“刚刚 / N 分钟前 / N 小时前 / N 天前”，详细列表与详情页按各自契约显示绝对时间。

收藏、打标、标签和风险统一由 `FileMarkers` 渲染：收藏只使用星形；打标只使用标签形；标签只显示颜色点和名称；风险使用紧凑色点/图标与短标签。不得再次在这些标记前拼接文件类型图标。hover、pressed、selected 只能改变颜色或背景，不能改变尺寸、定位、数量或可见性。

## 5. 四种文件视图的信息契约

| 视图 | 核心用途 | 必须展示 | 不展示/收起 |
| --- | --- | --- | --- |
| 详细列表 | 查找、比较和批量管理 | 图标/预览、名称、收藏、打标、风险、标签、类型、文件大小、修改时间、桌面操作 | 文件夹大小显示 `—`；移动端操作收进菜单 |
| 详细网格 | 视觉浏览且保留常用信息 | 大图标/预览、名称、收藏、打标、风险、标签、文件大小、修改时间 | 文件夹大小不计算也不占位 |
| 紧凑列表 | 高密度浏览 | 图标、名称、类型或大小、修改时间；桌面双列 | 标签详情和逐项完整操作 |
| 紧凑网格 | 最高密度视觉浏览 | 图标/预览、名称 | 标签、大小、收藏、表头和操作 |

目录列表页禁止自动递归计算文件夹大小。文件夹大小只在用户打开详细信息后异步计算，并提供加载、取消和失败状态。

## 6. 详细列表：推倒重做

### 6.1 桌面 DOM

使用语义 `<table>`，表头与数据行必须共享同一套 `<colgroup>`。不要再用 `.item.header` 和每行独立 Grid 模拟表格，也不要把文件图标放在列模型之外。

列定义：

| 列 | 建议宽度 | 对齐 | 内容 |
| --- | --- | --- | --- |
| 名称 | 自适应，最小 320px | 左 | 48px 图标/缩略图、两行内名称、收藏/打标、标签/风险 |
| 类型 | 150px | 左 | 中文文件类型 |
| 大小 | 104px | 右 | 文件大小；文件夹为 `—` |
| 修改时间 | 168px | 左 | `YYYY/M/D HH:mm` |
| 操作 | 176px | 右 | 详情、重命名、移动、下载、删除 |

行高基准 64px；名称含标签时允许 72px，但同一行所有单元格垂直居中。表头高 44px，背景为二级表面，只保留底部分隔线和列间极浅边界。取消列宽拖拽功能及相关 handle；列宽由 `colgroup` 和容器响应式决定。

表头名称、类型、大小、修改时间可点击排序。只在当前排序列显示箭头；悬停只使用浅灰背景，不显示大面积蓝块或位移。键盘可聚焦并支持 Enter/Space。

操作图标默认无背景和边框，悬停时显示 32px 浅色圆形/圆角底；删除仅在悬停/聚焦时变红。不能给五个按钮永久套白色方框。

文件夹与文件只使用一条带间距的分组分隔行，不重复用大号“文件夹”“文件”标题占用空间。选中状态为整行浅蓝背景和左侧 2px 主色强调，文件类型图标保持原色，不得变白或消失。

### 6.2 移动端专用 DOM

容器不足 900px 时不渲染桌面 `<table>`，改用 `DetailedMobileItem`：

```text
┌ 图标  文件名（最多两行）                 ⋮ ┐
│       类型 · 文件大小/文件夹 · 修改时间    │
│       [标签] [风险]          ☆收藏  打标    │
└──────────────────────────────────────────┘
```

- 图标/预览 `48×48px`，名称两行省略，不得只剩两三个汉字。
- 文件夹元信息不保留空的大小位置；显示“文件夹 · 修改时间”。
- 收藏和打标为稳定图标，不因 hover、selected、pressed 改变位置。
- 详情、重命名、移动、下载、删除进入右上角更多菜单/底部 Action Sheet，避免一行五个图标。
- 卡片最小高度 92px，左右 12px，卡片间 8px；不显示桌面表头，不产生页面横向滚动。

## 7. 详细网格与紧凑视图

### 7.1 详细网格

删除 `columnsResize()` 及任何运行时宽度写入。桌面使用 `repeat(auto-fill, minmax(180px, 1fr))`；卡片最大宽度可由容器均分，不设置与 JS 冲突的 `width`。

手机固定两列，列间距 8–10px，页面左右留白 12px。图标/预览建议 `72×72px`；名称居中、最多两行；文件大小仅文件展示；标签和风险独占一行或紧凑换行；修改时间置底。收藏和打标位于右上角两个固定热区，均必须可见。卡片不能用大 `min-height` 将信息推到四角，也不能出现无意义的大面积空白。

### 7.2 紧凑网格

遵循 Windows 11 大图标布局：图标/预览在上、文件名在下并居中。桌面高密度自动填充，手机两到三列取决于容器能否保证单卡至少 108px。禁止出现“名称 / 类型 / 操作”表头。

### 7.3 紧凑列表

桌面在容器 `>= 900px` 时双列，每项包含图标、名称和一行关键元信息；手机单列。双列是项目排列，不是把一个文件拆成两组不对齐字段。

## 8. Markdown 编辑与预览重构

### 8.1 统一主题源

应用主题是唯一事实源。使用 `document.documentElement.classList.contains("dark")` 或响应式主题 Store，禁止用完整 `className === "dark"`。Vditor、预览 CSS 和 highlight.js 必须订阅同一主题变化。

浅色模式：编辑器、工具栏、预览正文均为白色/浅灰；深色模式只有在用户明确启用时才加载。主题切换后需要替换 highlight.js CSS，不能因“已加载”标记永远保留旧主题。

### 8.2 编辑模式

- Vditor 编辑区使用一级表面，正文主文字，当前行使用极浅主色背景。
- 工具栏与编辑区之间使用 1px 边框，不使用整块深蓝画布。
- 编辑、分屏/大纲、预览的活动按钮使用统一浅蓝选中态。
- 大纲面板在窄屏改为抽屉，不挤压正文到不可读宽度。
- Markdown 的行号开关必须出现在顶部工具栏，与普通文本编辑器保持一致；默认关闭，并按用户持久化。

### 8.3 代码块

浅色代码块：背景 `#F6F8FA`、文字 `#24292F`、边框 `#D0D7DE`、圆角 8px，不使用深蓝背景和重阴影。深色主题可使用深色代码块，但对比度至少满足 WCAG AA。

语言处理规则：

1. 围栏声明语言（例如 Markdown 中的 Java 代码围栏）时按声明语言高亮并显示语言标签。
2. 未声明语言时，对受控语言集合执行自动识别；置信度不足按纯文本处理。
3. 未知语言不能报错，也不能错误套用其他语法。
4. “插入代码块”动作打开语言选择器，选择结果写回 Markdown 围栏，保证保存后仍可复现；不能只在当前 DOM 临时选择。
5. 预览代码块右上角提供语言标签和复制按钮。

### 8.4 行号

将 `highlightAndAnnotateCodeBlocks(container)` 改为接收 `{ showLineNumbers }`。只有开启时才包装行并添加 gutter；关闭时不创建伪元素、不保留 3em 空白，也不出现截图中的透明框。设置应按登录用户持久化；若当前后端没有通用用户偏好字段，可先使用带用户 ID 命名空间的 localStorage，并在 Spec 实施记录中标明迁移点。

### 8.5 CSS 拆分

将 `mdPreview.css` 拆为：

- `markdown-content.css`：标题、列表、表格、引用、链接等正文排版。
- `markdown-code.css`：代码块、语言标签、复制、行号和高亮主题。
- `vditor-overrides.css`：仅封装第三方 Vditor 边界。

项目自有组件禁止 blanket `!important`；只有覆盖第三方内联/高优先级样式且无法通过配置解决时，才在 `vditor-overrides.css` 中局部使用并写明原因。

## 9. 建议组件结构

```text
frontend/src/components/files/
├─ FileListing.vue              # 数据、筛选、排序与视图编排
├─ views/
│  ├─ DetailedTable.vue         # 桌面语义表格
```

## 10. 必须删除的旧机制

实施不能只新增文件，必须同时删除已被替代的代码：

- 删除 `columnsResize()`、`windowsResize()` 中针对网格宽度的 CSSStyleSheet 改写。
- 删除 `.details` 的 `min-width: 52rem` 手机横向表格方案。
- 删除旧 `.item.header` 模拟表头及列宽拖拽 handle 的全部样式和残留逻辑。
- 删除 `listing.css`、`mobile.css` 中重复控制四种视图的旧规则，不能留在前面再靠文件末尾覆盖。
- 删除移动端永久隐藏 `.tag-btn` 的规则。
- 删除无条件渲染移动端选择栏的逻辑。
- 删除浅色模式强制深色代码块、无条件 `has-line-numbers` 和固定 gutter 的规则。

## 11. 实施红线

- 禁止在 `listing.css` 或 `mdPreview.css` 文件末尾追加“最终修复/最终覆盖”区块。
- 禁止通过 `position: absolute` 和魔法像素让表头暂时对齐某一张截图。
- 禁止手机详细列表横向滚动桌面表格。
- 禁止通过隐藏名称、标签或操作来解决溢出；应切换为正确的移动组件。
- 禁止目录列表自动递归计算文件夹大小。
- 禁止浅色模式下固定使用深色 Markdown 编辑器或代码块。
- 禁止用文字字符、Emoji 或自绘 SVG 替代项目现有图标库。
- 禁止改变现有收藏、标签、权限、搜索 API 协议；若发现接口问题，单独记录，不与 UI 重构混改。

## 12. 任务与提交拆分

每个提交只完成一个可独立验证的行为，提交内容使用中文 Conventional Commits：

1. `refactor(views): 拆分文件列表视图组件`
   - 建立视图组件边界和共享数据模型；外观暂不大改。
2. `fix(mobile): 重构移动端工具栏与面包屑`
   - 完成 leading/center/trailing、单行面包屑和不透明菜单。
3. `refactor(details): 重建桌面详细列表`
   - 使用语义表格、统一列定义、排序和稳定选中态；删除列宽拖拽。
4. `refactor(details): 新增移动端详细列表卡片`
   - 移动端不再渲染表格，操作改为 Action Sheet。
5. `refactor(grid): 重建详细网格与紧凑视图`
   - 删除 JS 列宽控制，完成手机两列和信息契约。
6. `fix(selection): 修复移动端选择工具栏常驻`
   - 按多选状态条件渲染并适配安全区。
7. `refactor(markdown): 统一编辑与预览主题`
   - 拆分 Markdown CSS，浅色模式恢复浅色编辑与代码块。
8. `feat(markdown): 新增代码语言识别与行号开关`
   - 语言选择写入围栏，行号可切换并持久化。
9. `test(ui): 补充文件视图与 Markdown 验收测试`
   - 增加关键状态的组件、交互和视觉回归测试。

若某一步必须同时修改大量旧 CSS，仍应在同一提交中完成“新契约生效 + 对应旧规则删除”，不能把删除债务留给后续。

## 13. 验证矩阵

### 13.1 视口

- 手机：`360×800`、`390×844`。
- 平板：`768×1024`。
- 桌面：`1366×768`、`1920×1080`。
- 桌面另测侧边栏最小、默认、最大三种宽度。

### 13.2 文件状态

每种视图至少覆盖：空目录、单个文件、文件夹与文件混合、超长中文名、超长英文名、无后缀文件、图片/视频缩略图、标签、多标签、风险标识、收藏、选中、多选、无权限动作。

### 13.3 Markdown

覆盖编辑、预览、分屏/大纲；普通段落、表格、引用、任务列表；Java、JavaScript、Shell、未知语言和无语言代码块；行号开/关；浅色/深色切换；长行横向滚动；复制代码。

### 13.4 自动验证

在 NAS 源码目录执行，不进行部署：

```bash
/opt/node24/bin/corepack pnpm test
/opt/node24/bin/corepack pnpm typecheck
/opt/node24/bin/corepack pnpm lint
/opt/node24/bin/corepack pnpm build
```

若引入组件测试，优先使用 Vue Test Utils；若当前依赖中没有，新增依赖必须单独说明。关键断言包括：

- 手机宽度不渲染详细表格和表头，页面无横向溢出。
- 桌面表头与每行五列的 bounding box 左右边界一致。
- 未进入多选时选择栏不存在。
- 手机工具栏菜单在左，搜索和更多在右。
- 手机网格始终两列且名称至少可显示两行。
- 文件夹大小为 `—` 或不占位，且没有触发递归大小请求。
- 行号关闭时代码块不存在 gutter；开启后行号与代码行一一对应。
- 浅色主题下编辑器和代码块不使用深色背景。

## 14. 人工视觉验收标准

1. 在相同视口和相同测试数据下分别截图旧版与新版，成对比较，不以单张截图主观判断完成。
2. 所有表头与内容列对齐误差不超过 1px；行高、垂直居中和分隔线在滚动过程中不漂移。
3. 360px 手机上无页面级横向滚动；长名称不会挤掉主操作，也不会只显示两三个字。
4. 所有点击目标稳定，不因 hover、pressed、selected 改变位置或消失。
5. 固定工具栏不得遮挡最后一个文件项；需要加入对应底部内边距。
6. 浅色 Markdown 编辑与预览视觉连续，代码块清晰但不形成大面积黑块；行号关闭后左侧没有空框。

## 15. 完成定义
