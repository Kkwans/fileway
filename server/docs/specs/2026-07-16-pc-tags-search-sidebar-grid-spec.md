## 1. 目标与执行约束

本轮以用户 2026-07-16 提供的 7 张 PC 端标注图和逐条清单为唯一需求基线。目标不是继续追加局部 CSS 覆盖，而是清理重复规则、建立可复用组件和稳定的数据/交互契约。

- 所有用户要求都映射为唯一任务编号，并在本文件持续更新状态。
- 每个行为变更先写失败测试，再做最小实现，完成后运行聚焦测试、类型检查和构建。
- 一个提交只处理一个模块，使用中文 Conventional Commits。
- 延续现有浅色、克制、内容密集型文件管理器语言；不引入新主题、新字体、渐变或夸张阴影。
- 复用现有 Material Icons 和语义色令牌；交互态不得造成尺寸或位置抖动。
- Windows 只修改同步源码；真实 Git 提交和推送在 NAS 仓库核验执行。本轮不部署。

## 2. 统一视觉与交互契约

### 2.1 视觉层级

- 一级模块：用户、收藏夹、标签、存储卷、目录分类。统一 44px 标题行、12px 圆角、浅色模块表面和 1px 边界。
- 二级分组：收藏分组、目录分类分组。统一 40px 行高、10px 圆角、较一级更弱的表面层级。
- 三级条目：收藏路径、标签、存储卷、分类路径。统一图标列、主信息列、计数/动作列。
- hover 只使用比静态卡片更浅的状态层，不改变宽度、高度或圆角，也不超出父卡片边界。
- 图标与文字采用固定列对齐；可点击图标保留至少 36×36px PC 命中区。

### 2.2 间距与形态

- 使用 `4 / 8 / 12 / 16 / 24px` 间距体系。
- 普通卡片圆角 10–12px，输入框与按钮 8px；颜色点保持正圆。
- 同层级计数徽标统一高度、最小宽度、数字字体和背景，不按模块各自实现。
- 删除类操作必须二次确认；确认信息靠近触发对象，不放到无关列表末尾。

## 4. 数据与组件设计

### 4.1 标签颜色状态

新增纯函数：

- `normalizeTagColor(color)`：统一十六进制大小写。
- `getUsedTagColors(tags, excludingId?)`：计算禁用色集合。
- `isTagColorAvailable(tags, color, excludingId?)`：创建/编辑校验。

UI 禁用只是反馈层，Store 的 `createTag` / `updateTag` 也必须拒绝重复颜色，避免绕过界面。失败应返回可识别结果，由弹窗显示中文就地提示。

### 4.2 共用结果模型

```ts
interface UnifiedResultItem {
  key: string;
  name: string;
  fullPath: string;
  parentPath: string;
  url: string;
  isDir: boolean;
  size?: number;
  modified?: string;
}
```

搜索 API 和标签路径分别适配到该模型；展示组件不关心数据来源。右键菜单只接收模型和权限，不直接依赖搜索/标签页面内部状态。

### 4.3 侧边栏层级组件

```text
SidebarPrimaryNavigation
SidebarUserCard
SidebarSection        # 一级模块
SidebarGroup          # 二级分组
SidebarItem           # 三级条目
SidebarCountBadge
SidebarConfirmPopover
```

先建立视觉/交互契约，再逐模块迁移；迁移完成后删除 `sidebar.css` 中重复定义同一选择器的历史覆盖块。

### 5.1 自动测试

- 标签：颜色规范化、重复颜色拒绝、编辑自身颜色允许、颜色禁用集合。
- 结果路径：中文/编码路径、文件与目录父路径、根目录、尾部斜杠。
- 结果动作：打开所在位置路由、预选路径、权限动作集合。
- 侧边栏：默认折叠状态迁移、收藏排序、单位格式、共享目录分类。
- 详细网格：信息契约函数确保目录无 size、详细网格标签仅输出颜色标记。

### 5.2 静态与构建验证

```text
pnpm test -- <聚焦测试>
pnpm typecheck
```


- 以用户 7 张标注图的相同 PC 宽度复核每个红框问题。

- 搜索/标签：当前目录/全局、文件/目录、中文长路径、右键菜单。
- 侧边栏：默认展开态、所有层级 hover、拖动排序、空分组、长名称。
- 详细网格：文件夹/文件、有标签/无标签、风险目录、选中态。
