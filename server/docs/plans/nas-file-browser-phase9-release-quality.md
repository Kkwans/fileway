# NAS File Browser Phase 9 发布质量修订计划

## 目标

Phase 9 是原 P0–P2 完成后的发布质量修订。按 R-P0、R-P1、R-P2 顺序实施，优先恢复 NAS 宿主根目录与关键交互，再完成侧栏、文件列表、存储工具、任务中心、操作历史和全站视觉验收。

功能正确性、UI 质量和用户体验优先。性能不设固定提升比例，但不得明显回退。不得删除既有功能、真实缩略图、用户数据或移动端“单击按压反馈、双击打开、长按选择、滚动不误触”契约。

## 已确认决策

- 管理员读写 NAS 宿主机原生根目录；普通用户继续受 Scope 和权限限制。
- 桌面侧栏可折叠为约 72px 图标轨，移动端保留完整抽屉；状态写入用户偏好数据库。
- 特殊前缀内置 `. @ # ~ $` 并支持自定义；默认可见、展开，隐藏仅影响目录列表。
- 前缀折叠按用户全局保存，在目录、布局和设备间同步。
- 媒体标题固定左上角，以白色高对比文字配局部深色遮罩。
- 风险分类由 Backend 统一返回，使用目录边界匹配；风险状态使用原生文件/文件夹图标，不叠加小圆点。
- 任务需处理只包含失败和中断；已取消独立分类；批量操作只作用于当前筛选结果。
- 一键归档持久保存且可恢复，不删除任务；结果优先弹窗展示。
- 图标使用固定版本、本地打包的 `@lucide/vue`，通过项目语义 Icon 组件集中管理。
- 每个独立模块通过测试后立即中文 Conventional Commit、push、部署并在 TX5pro 上验收。

## R-P0

### Phase 9A：NAS 宿主根目录

- Compose 将宿主 `/` 读写挂载到容器 `/srv`，并将 `FB_ROOT` 改为 `/srv`。
- 暂时保留现有显式卷挂载，不改变其他运行契约。
- 卷发现相对 Server Root 扫描并只返回虚拟路径，禁止把容器根目录当作 NAS 根目录。
- 管理员入口显示“NAS 根目录”，普通用户显示“我的文件”。
- 部署前备份 Compose 和数据库，保留当前 r10 镜像作为回滚点。

### Phase 9B：媒体、面包屑和风险图标

- 媒体预览建立独立 Chrome，修复标题颜色、位置和左右导航的光学居中。
- 面包屑使用稳定的 Header offset，滚动前后顶部间距保持一致。
- Backend 统一 `riskLevel: low | medium | high`；修复 `/etc2` 等相似前缀误判。
- 高风险覆盖典型 Linux 系统目录及现有 NAS 系统目录；Docker、索引、缩略图等为中风险。
- 四种文件布局改用原生语义风险图标；真实媒体缩略图继续保留。

## R-P1

### Phase 9C：侧栏、特殊前缀和文件操作

- 桌面完整侧栏与图标轨共用导航模型；收藏、标签、分类、存储卷在图标轨中使用锚定浮层。
- 用户模块、菜单和登出统一对齐，正文不小于 14px、辅助文字不小于 12px，触摸目标不小于 44px。
- 新增版本化 `listingPreferences`，支持内置和自定义前缀的显示、隐藏、折叠和排序。
- 旧 `hideDotfiles=true` 幂等迁移为 `.` 前缀隐藏，并同步所有现有用户。
- 四种布局共用一个分组后的可见列表模型；隐藏/折叠项不参与分页、选择、范围选择和键盘焦点。
- 详细网格使用底部操作条；详细列表默认保留收藏、标签和更多菜单，减少常驻操作噪声。

### Phase 9D：存储工具

- 保留重复文件和空间分布的单工作区切换，删除重复标题、英文 Kicker 和巨大说明卡。
- 流程统一为选择范围、确认并运行、查看结果；步骤编号按真实状态连续显示。
- 最近扫描显示范围、时间、结果状态和关键指标。

### Phase 9E：任务中心和操作历史

- 任务筛选为全部、进行中、需处理、已取消、已完成、已归档。
- Task 增加 `archivedAt`；新增归档、取消归档和筛选快照批量接口。
- 批量动作带 `expectedCount`；匹配数量变化返回 409，要求重新确认。
- 任务结果优先弹窗；完整报告返回后恢复筛选、滚动位置并定位原任务。
- 任务和历史使用服务端筛选与每批 30 条游标分页。
- 历史时间线由父级连续轨道绘制，刷新按钮只在加载时旋转。

## R-P2

### Phase 9F：全站审计与发布验收

- 逐页检查错位、过小字号、横向溢出、低对比度、操作密度、图标语义、重复层级和异常空白。
- 保留现有品牌、配色方向、信息架构和真实缩略图，不引入装饰性彩色左轨、胶囊堆叠或逐项级联动画。
- 每个问题必须先稳定复现，再最小修复并补回归测试。

- Backend：`go test ./...`，CI 执行 race test。
- Docker：镜像构建、Compose config、健康检查、日志和真实端点。
- TX5pro Playwright：桌面、窄容器、390px 手机、Light/Dark、Reduced Motion、键盘、触屏模拟、四种文件布局、特殊前缀、风险、媒体、侧栏、存储工具、任务和历史。
- 视觉比较使用相同 viewport 和稳定状态；发现问题在当前优先级内修复并重新提交、推送、部署、验收。
- 禁止强推、rebase、amend、清理镜像或删除用户文件。始终保留 `.codex-tmp/`、`database/` 和同步冲突 Compose 文件。

## 回滚

- 每次部署使用明确不可变镜像标签并保留上一版本。
- 数据结构迁移前备份数据库；Compose 变更前备份原文件。
- 验收失败时恢复上一镜像、Compose 和必要的数据库备份，重复相同健康检查；不使用 Git 历史重写作为回滚手段。
