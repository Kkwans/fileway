# PC 端登录、侧边栏与共享文件夹动态识别方案

## 目标

本轮只处理用户已确认的 PC 端残留问题，不部署：

1. 登录状态提示全部使用原生中文，桌面端登录卡片扩大，移动端尺寸保持紧凑。
2. 侧边栏建立统一的水平基线、一级模块头和二级分组样式。
3. 侧边栏滚动条不再引起卡片宽度变化，默认隐藏滑块，仅滚动时显示。
4. 调整宽度继续保留足够命中区域，但视觉上只呈现边界分隔线，不显示蓝色拖拽条。
5. 共享文件夹从绿联系统注册数据的只读投影动态读取，不再扫描卷根目录猜测。

## 根因

### 登录页

- `auth.ts` 会使用 `inactivity` 作为退出原因。
- `Login.vue` 自己维护了一份不完整的映射，并在未知值时直接输出原始字符串。
- 桌面和移动端共用 `28rem` 卡片上限，没有桌面断点。

### 侧边栏

- 收藏夹、标签使用“主按钮 + 工具区”，存储卷、目录分类使用另一套独立按钮结构。
- 历史 CSS 存在多轮重复覆盖，水平内边距、箭头位置和卡片宽度没有单一规范。
- 滚动条出现时占用内容宽度；拖拽热区直接用蓝色背景表达，视觉权重过高。
- 目录分类的二级条目拆成“导航按钮 + 展开按钮”，没有复用收藏分组的统一外壳。

### 共享文件夹

- 后端 `shared` 分类依赖固定目录名称列表。
- 绿联的权威注册记录位于 PostgreSQL `nasdb.ug_shared_folder`，不能用卷根目录扫描替代。
- 应用容器没有 PostgreSQL 凭据和 socket；为读取而修改 `pg_hba.conf` 会扩大系统风险。
- `storage_serv` 会依据数据库注册记录生成 `/etc/samba/smbshare.conf`，可作为无凭据、只读、动态的系统投影。

## 设计与实现

### 1. 登录页

- `Login.vue` 只调用 `getLogoutReasonText`，不再自行解释退出原因。
- 新增 `inactivity` 映射：`长时间未操作，登录状态已失效，请重新登录`。
- 未知退出原因只显示安全的中文兜底，不透传上游英文或内部代码。
- 桌面端卡片宽度调整到 `min(100%, 34rem)`，增加留白和控件高度；`<= 480px` 保持原移动端宽度与间距。

### 2. 统一一级模块头

- 新增 `SidebarSectionHeader.vue`。
- 收藏夹、标签、存储卷、目录分类统一使用：
  - 相同卡片外壳；
  - 相同图标、标题、工具区、展开按钮网格；
  - 展开箭头围绕中心旋转；
  - 工具区差异通过插槽传入。

### 3. 统一二级分组

- 新增 `SidebarGroupHeader.vue`。
- 收藏夹分组和目录分类一级条目共享相同的：
  - 圆角、边框、背景和悬停状态；
  - 数量徽标；
  - 操作区和展开箭头布局。
- 收藏分组主区域用于折叠；目录分类主区域用于进入第一条路径，箭头独立控制折叠。

### 4. 水平基线、滚动与调整宽度

- 侧边栏统一使用 `--sidebar-inline-gutter`，用户卡片、普通菜单、一级模块卡片共用同一左右边界。
- 始终为滚动条保留固定窄槽，避免出现滚动条时卡片宽度变化。
- 滚动时添加 `is-scrolling` 状态，仅此时显示滚动条滑块；停止滚动后淡出。
- 调整宽度热区仍为 12px，实际可见部分由伪元素绘制为 1px 边界线；悬停/拖动仅加深边界并增加轻微阴影。

### 5. 动态共享文件夹

- Compose 将 `/etc/samba/smbshare.conf` 只读挂载为 `/run/ugreen/smbshare.conf`。
- 后端每次请求 `/api/categories` 时读取该文件，只采集具备绝对 `path` 的已注册共享 section。
- 排除 `personal_folder` 和 `%H` 等非具体共享路径。
- 配置可读且存在注册记录时，以记录中的路径为唯一共享文件夹集合；不混入历史静态清单。
- 配置暂时不可读时才使用既有规则兜底，避免目录分类完全失效。
- 同时挂载 `/mnt`，使绿联注册的外接盘共享目录能够实际导航。

## 验收标准

- 登录地址携带 `logout-reason=inactivity` 时不出现英文，显示固定中文提示。
- PC 登录卡片明显大于移动端，移动端不横向溢出。
- 四个一级模块的左边界、高度、展开按钮中心点完全一致。
- 用户卡片、普通菜单、二级操作菜单与一级模块左边界一致。
- 侧边栏滚动前后，所有卡片宽度不变化；停止滚动后滑块隐藏。
- 拖拽边界默认只有细分隔线，悬停或拖动时仅加深/加阴影。
- 收藏分组与目录分类一级条目使用相同组件和视觉结构。
- 后端测试证明：配置中的新增注册路径会加入共享分类，未注册的一级目录不会被猜测加入。
- 前端测试、类型检查、Lint、构建以及后端相关 Go 测试通过。
