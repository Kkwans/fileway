# 移动端触控与紧凑网格修复方案

## 目标

修复移动端四种文件视图共用的触控事件链，并调整紧凑网格在手机宽度下的列数。改动只覆盖本轮已经明确的需求；“详细网格视图”下尚未提供具体内容的条目不做推断实现。

## 问题根因

1. `ListingItem` 同时处理 `touch*`、合成 `click` 与 `contextmenu`，触摸结束后仍会进入 PC 点击选择逻辑。
2. 长按只调用通用选择函数，没有打开现有移动端底部操作面板。
3. 条目级 `contextmenu` 没有阻止冒泡，父级 `FileListing` 会继续打开 PC 右键菜单。
4. 移动端紧凑网格目前中图标和大图标同为两列，小图标只有三列，信息密度不符合要求。

## 交互契约

| 编号 | 场景 | 预期行为 |
| --- | --- | --- |
| MOB-01 | 移动端单击条目 | 不打开、不选择、不弹菜单 |
| MOB-02 | 移动端连续双击同一条目 | 打开文件或进入文件夹 |
| MOB-03 | 移动端长按条目 | 选中当前条目并打开底部操作面板 |
| MOB-04 | 移动端触发原生 `contextmenu` | 阻止默认行为和冒泡，不显示 PC 右键菜单 |
| MOB-05 | 滑动、取消触摸 | 取消长按与双击候选状态，不留下选择或遮罩 |
| MOB-06 | PC 鼠标点击、双击、右键 | 保持现有行为不变 |
| GRID-01 | 手机端紧凑网格中图标 | 每行三列 |
| GRID-02 | 手机端紧凑网格小图标 | 每行四列 |

## 技术方案

### 1. 纯函数触控契约

在 `layoutContract.ts` 中增加移动端触控动作判定，区分 `none`、`open`、`select-and-menu`。组件只负责收集触摸次数、是否长按、是否移动，业务动作由纯函数结果驱动，以便用单元测试锁定行为。

### 2. 统一 `ListingItem` 触控状态机

- 首次轻触只记录双击候选，不进入通用 `itemClick`。
- 同一条目在时间窗内第二次轻触直接调用已有 `open()`。
- 长按达到阈值后，选中当前条目并打开已有 `mobile-item-action-sheet`。
- 触摸移动超过阈值或取消时清理计时器和候选状态。
- 延迟清理触摸标志，吞掉浏览器在 `touchend` 后派发的合成 `click`。

### 3. 隔离 PC 右键菜单

- 条目级移动端 `contextmenu` 调用 `preventDefault()` 和 `stopPropagation()`，不再进入选择或 PC 菜单流程。
- 父级 `showContextMenu` 在移动宽度下直接返回，形成第二层保护。
- PC 端继续沿用原右键菜单。

### 4. 紧凑网格列数

在手机断点下按尺寸类覆盖网格列数：中图标三列、小图标四列；大图标和超大图标保持现有密度。纯函数同步表达列数契约，避免 CSS 与测试认知漂移。
